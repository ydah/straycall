Using RSpec or Minitest?

Start by recording what your suite touches. Review the policy before enforcing it.

  1. 1Add to your Gemfile

    # Gemfile
gem "straycall"
    bundle install

  2. 2Record a test run

    bundle exec straycall --record -- bundle exec rspec

    Writes .straycall.recorded.yml. Review the observed access and save your approved policy as .straycall.yml.

  3. 3Run with your policy

    bundle exec straycall --config .straycall.yml -- bundle exec rspec

    With the default fail mode, disallowed calls are blocked and the command exits nonzero.

Choose how to respond.

Observe first. Enforce when you’re ready.

failDefault
Deny the call with EPERM and exit nonzero.
warn
Allow the call and report the violation.
record
Allow calls and write a policy for you to review.
prompt
Ask in the terminal. Deny when no TTY is available.

Built for Linux.
Honest about its limits.

Straycall uses Linux seccomp user notifications to pause selected syscalls. A separate supervisor checks your policy, then allows or denies each call.

Reports include Ruby backtraces when available, with a native-library fallback, and can be saved as versioned JSON.

Before you run

Requires Linux 5.5+ with seccomp user notifications and CONTINUE support, on x86_64 or aarch64, with MRI Ruby 3.1+. Container profiles must permit seccomp.

On unsupported platforms, non-MRI Ruby, or with STRAYCALL=0, the wrapped command runs normally without enforcement.

A guardrail for accidental access

Straycall is not a security sandbox for hostile code. Symbolic links, existing file descriptors, and pointer-based policy checks leave gaps.
